# 用户操作指南

## 本机启动

依赖和前端编译完成后，在 PowerShell 运行 `./scripts/start-local.ps1`。默认仅监听本机；网页为 http://127.0.0.1:4173，API 为 http://127.0.0.1:8000。持久数据和日志位于项目工作根 private/runtime，脚本不会覆盖已有端口上的服务。

## 巡检包

先在服务器本机登记测量场景及对齐，按 [离线导入指南](../OFFLINE_IMPORT.md) 从接收目录导入正式包。网页不能上传原始包或指挥车辆。诊断包、缺失必需证据、身份冲突均须保留拒收原因；不要修改归档来消除错误。导入后仍需人工核对首末帧与地标，完成现场验收。

## 设备证据和读数

导航进入“设备证据与读数”。首次应为空。登记设备之前必须已登记场景版本，明确代理标记族、ID、位置、匹配容差和三条通道单位；验收地标不得重用为设备 ID。

展开观测后使用“按已记录的标记计算候选”，在复核表单选择设备或“不确认设备”，填写原因并保存。服务端检查场景一致性，追加保存决定；若已有更新，须刷新后重新判断。结构化记录入口保留给受审查的外部数据。独立身份模式记录认证人员 ID；共享/本机模式下人员标签仍是自报信息。

读数导入必须明确深基点、浅基点、差值各自源字段与单位，差值不自动推算。历史映射使用 mapping_version、timezone、timestamp_field、asset_field、asset_ids、fields、units、validity_seconds、quality_field、quality_values 和 source_reference；rows 为逐行原字段，source_type 明确区分 replay 与 simulation，run_id 指向已知运行。逐行保存，错误行在结果中列出，不能把部分导入说成全部成功。

选中设备后，默认分析当前时刻之前的有效读数；输入含时区的时间可回溯。观测行可查看观测采集时刻的设备关联，未来读数不会用于该时刻。无阈值显示待复核，无有效期不会显示为当前有效。历史曲线不使用随机数填空。JSON 报告含输入、排除原因、映射版本、规则和趋势来源；规则建议不构成工程安全结论。

## 访问保护和备份

默认 API 仅允许无转发头的本机访问。通过反向代理或 Docker 使用时，在私有环境配置 ASTRA_API_TOKEN，前往“访问授权”输入一次，建立 8 小时 HttpOnly/SameSite 会话。环境密钥不提交 Git；网络部署须配置 HTTPS。所有 API（健康信息除外）和 WebSocket 均受访问检查。密钥轮换使现有会话失效。也可使用独立身份模式区分查看者、复核者和操作员；当前身份显示在设备证据页，部署方法见 [访问身份说明](../development/ACCESS_CONTROL.md)。

SQLite 备份应包含 instrument_assets、instrument_records、instrument_audit；新验证器将这些记录纳入摘要。旧版只含运行台账的备份不能代替新增业务数据备份。保持归档校验、独立介质备份、人工验收和清理门槛。

## 当前限制

站点自动索引、三维设备点选、批量派生和人工复核已实现。通用无标记识别仍需要真实训练数据。客户数据库未读取或恢复；真实字段关系、单位和阈值未获验证。全部测试未执行，编译完成不代表功能验收。


### 站点回放和设备读数

进入任务回放并选择运行。在“站点结果与回放”查看完成、跳过和失败记录，点击“定位回放时刻”会暂停并跳转。超出已导入轨迹范围的记录不能跳转。旧归档可点“从归档重新索引”，过程会读取整个包进行完整性校验，耗时取决于包大小；原包没有站点档案时列表仍为空。

三维中的登记设备只来自当前运行绑定的场景版本。点击设备后查看选择时刻的深基点、浅基点和差值读数。设备没有实时连接时显示离线，不代表设备损坏。缺少有效历史读数、单位映射或阈值时应先补齐输入，不把待复核当作正常。路线完成不是图像识别成功，站点时间跳转显示的是车辆位置。


### 查看采集证据与派生观测

在站点列表点击“查看采集证据”，查看每次采集的开始、成功/失败、原因和记录哈希。成功采集可点击“派生标记观测”：系统从本地归档读取图片，并检查标定、图像尺寸、相机坐标系和仪器标记配置。缺少输入时显示阻塞清单；未找到已配置标记时不会生成观测。

此入口提供二维标记观测；尺寸、外参、完整位姿和误差预算齐备时，还提供待复核的米制位置估计。详情页分别列出像素误差、条件标准差和同步位移上界。结果不能当作设备身份确认、精度保证或工程安全结论。旧包缺少完整位姿时需后续新采集补齐，不能手工改动已归档包。图片保留在本地归档，页面显示证据元数据。


### 批量派生与暂停恢复

任务回放的站点区域新增“批量派生处理”。先从归档索引站点，再点击“创建 / 打开本运行批次”，系统将当前已索引的成功采集固定为处理清单。选择批次可查看完成、缺口和失败数量，以及分页明细。

“当前项结束后暂停”不会强行打断正在处理的包；看到运行项归零后即暂停。“继续未完成项”恢复暂停批次，“重试失败项”只重跑异常项，历史结果保留。缺少标定等输入不能靠重试修复。关闭页面不会取消批次，服务重新启动会继续原未完成项；处理版本升级时旧批次暂停，需要新建批次。

处理结束不等于识别、定位或验收通过。到对应站点“查看采集证据”，点击“刷新报告”查看具体结果和缺口。站点、报告、批次与明细均可翻页；新增数据请回首页刷新。

备份前暂停批次、等待当前项结束，并停止其他写入。该恢复功能尚未执行中断演练。
