# 车端与真实采集输入就绪

## 检查范围与证据

沿用现有车端准备入口与正式 v2 契约，不新增配置平台。详细记录留在私有交接目录，逐项记录原始位置、版本/日期、SHA-256、核对结果、适用范围和未完成项；原件保持不变。公开跟踪只记录技术结论和缺项类别。

| 必需项 | 核对依据 | 阻塞条件 |
| --- | --- | --- |
| 相机内参 | 实际部署的标定 URL、profile、相机/镜头身份、ROI、分辨率、内参原件及原始标定归档摘要 | 来源缺失、摘要不符、身份或成像设置不匹配；当前安装/焦距变化尚未复核 |
| 相机与车体外参 | 已启用配置、批准记录、测量来源、父子 frame 和光学坐标约定 | 候选结果冒充已启用值；缺少本次适用性或正式包外参证据 |

## 只读准备入口

先检查目标机现有 `scout_bringup.preflight` 的实现及安装来源。已知版本的 `--start-*` 参数仅选择检查项，不启动节点。下面的调用检查软件、CAN 状态和路线前提，不启动相机或雷达，也不请求控制话题；实际运行的 launch、service、bag 操作不属于此步骤。

```bash
# 两个变量须指向本次实际工作区和私有配置。
: "${SCOUT_WORKSPACE:?请设置实际车端工作区}"
: "${SYSTEM_CONFIG:?请设置实际私有 system.yaml}"
source /opt/ros/humble/setup.bash
source "$SCOUT_WORKSPACE/install/local_setup.bash"
PYTHONDONTWRITEBYTECODE=1 python3 -m scout_bringup.preflight "$SYSTEM_CONFIG" \
  --workspace-root "$SCOUT_WORKSPACE" \
  --start-camera false --start-livox false \
  --start-scout true --start-fast-lio true --start-teleop true \
  --start-inspection true --start-route true
```

该入口不覆盖输出盘容量、正式包 v2 输入、相机实时标定诊断、时间同步精度或完整安装一致性。还须只读查询安装模块、实际输出挂载点和剩余字节，并逐项核对上表。不要调用 `/inspection/start` 或会创建文件的存储探针来代替只读容量检查；预检成功也不构成采集许可。

## 2026-10-21 核对结果

结论：**未就绪；Issue #3 保持未完成。**

- 已实读部署配置与标定原件，内参 profile、标定归档摘要、历史外参批准记录及已启用配置的相关引用一致。历史证据的适用范围和当前硬件状态仍须区分。
- 实际输出盘可用空间低于现有启动门槛，门槛和原始数据未修改。
- 目标机仍使用旧车端部署并有未提交改动；正式 v2 验收导出入口、共享契约模块及 BagIt 依赖缺失。版本、安装来源和差异已在私有记录中保存。
- 已检查范围内未找到本次实际标靶尺寸与误差、正式场景版本/对齐及完整定位策略。主机时钟同步状态不能证明图像与位姿时间误差。
- 补查目标机用户目录、历史验证目录及挂载目录，发现的是历史合成对齐夹具和演示场景。即使夹具带有 `onsite_verified` 字段，其方法/来源仍为测试，不能当作现场证据。
- 既有只读预检返回路线未配置、控制器未验收；两项保持阻塞。该预检不替代容量和正式包核对。
- 本次只做文件/摘要、部署依赖、系统状态和预检读取；没有安装、部署、启动传感器、控制车辆、处理巡检包或执行项目测试。

下一步须保留设备脏工作区和私有标定，补齐正式 v2 部署及依赖，提供满足原门槛的输出存储，并完成本次标靶/场景/同步/误差预算和现场适用性核对。各项完成后重新记录就绪证据，不能用本次缺项清单关闭任务。
