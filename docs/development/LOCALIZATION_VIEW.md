# 本运行观测定位上三维

任务回放增加独立的观测定位图层与分页列表，消费已有的 InstrumentLocalization，不把观测转换为设备台账或缺陷事件。黄色线框方块表示定位记录中的标记中心，显示符号大小不代表标靶或设备实际尺寸。相同标靶的多次观测分别保留，不聚合成一个已确认设备。

## 服务端只读投影

`GET /api/instruments/runs/{run_id}/marker-localizations` 默认每页 25 条，`limit` 最大 100，`cursor` 为上一页最后一个定位 ID。沿用所有业务 API 的身份保护，不返回归档绝对路径，也不修改记录、资产、复核或验收状态。

服务端要求 v2 实录导入账本与任务的运行 ID、场景 ID/版本及对齐一致。SQL 连接同一运行的定位、观测及 marker-proxy-metric-v2 报告，不将手工或无报告记录解释为该处理器的标靶结果。这些记录仍可从原记录 API 读取。

每项继续核对：

- 定位与观测的 v0.3 模型、replay 来源、待确认溯源、处理器身份和报告引用；采集时间在运行范围内，相机标定引用与 inventory 一致。
- 报告 ID 由原包摘要、站点尝试、采集序号和处理器版本确定；这些值与报告输入一致。
- 本运行站点证据中存在唯一的成功采集，记录与图片摘要绑定导入 inventory；处理报告中的图像、source.json、内参和检测配置摘要一致。
- 有位置时额外核对米制策略、相机外参及场景对齐的摘要绑定。报告中必须有唯一的观测/检测/估计，标靶 ID 和位置与持久化定位一致，状态保持 needs_review。

该入口读取处理时保存的来源，不重新读取完整 MCAP、重算位姿或验证现场精度。来源冲突阻止整页投影并返回 422。原截图接口在读取图片时继续检查实际归档字节。

## 回放与证据

三维只显示列表本页有有限位置的记录；无位置记录保留原因与缺口，不用车辆或台账坐标代填。页面标明本页记录数及点位数，换页/刷新时清空旧结果，返回数据必须与当前运行、场景版本及对齐一致，取消及过期响应不能进入新运行。

点位使用 scene_local_yup 原坐标，不套资产打包矩阵。点击点位或“查看定位证据”暂停回放，在轨迹覆盖该采集时刻时跳转；没有覆盖时保留当前回放时刻。“定位三维点位”通过既有相机命令聚焦点位。黄色方框可单独开关，列表和证据仍可使用。点位是本页全程观测的静态位置，不按时间隐藏未来观测。

选择后展示对应报告的条件最大轴标准差、同步位移上界和图片摘要，并复用站点详情读取该报告及该次采集的原图与角点。指定报告按 ID 读取，不依赖它是否恰好在站点报告列表第一页；详情再次核对运行和站点身份。原站点页保留分页查看全部报告的行为。

条件误差不是实测残差或精度保证。设备身份与历史读数继续通过独立台账/复核链路查询；本功能不发起自动匹配、人工确认或车辆控制。

## 引擎边界

共享 TwinViewerProps 增量增加可选 `instrumentLocalizations`；原调用方省略时为空。新增 `localization` 选择类型与 `setInstrumentLocalizations` 引擎方法，使用 `localizationObjectId(localization_id)` 生成三维对象 ID。该函数位于无 Three.js 依赖的共享契约，业务页不会因此提前加载三维引擎。定位图层参与点选、相机聚焦、选择高亮及替换/卸载资源释放。

本阶段只执行编译、类型/静态检查、OpenAPI 生成和 diff 检查。新增投影、图层与请求隔离回归用例保留未执行；没有进行图片检测、位置求解、业务接口、前端视觉或实车验收。
