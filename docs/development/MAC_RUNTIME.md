# Mac 离线启动与数据持久保存

对应 [Issue #2](https://github.com/LeoAKALiu/field-inspect/issues/2)。入口为项目根目录的 `scripts/start-local.py`，使用 Python 标准库管理已有 Uvicorn 和 Vite preview，不安装额外运行依赖。当前提供实现和准备步骤，启动与数据保留验收尚未执行。

## 联网准备

在 Mac 准备 Node 20+、pnpm 9.15.0、Python 3.11+ 和 uv；保留项目原有锁文件。下面的安装和构建在准备阶段完成，现场不执行：

```bash
pnpm install --frozen-lockfile
(cd services/api && uv sync --frozen --no-dev)
pnpm build
```

完整保留 `services/api/.venv`、各 workspace 的 `node_modules`、`packages/contracts/dist`、`packages/twin-viewer/dist`、`apps/web/dist` 以及现有源码/演示资源。Python 虚拟环境与原解释器路径有关，准备完成后不移动项目或卸载解释器。换机、换代码版本或升级依赖应重新完成准备和独立运行验证；启动器不下载、不更新、不重新构建网页，也不重置数据库。

## 持久目录与访问配置

默认持久根目录为 `~/Library/Application Support/FieldInspect`，与源码分开；可以显式设置 `FIELD_RUNTIME_ROOT`。数据库和导入根目录仍复用 `TWIN_DB_PATH`、`TWIN_IMPORT_ROOT`，未设置时分别使用持久根目录的 `twin.db`、`imports/`。路径必须为源码目录以外的绝对路径，不能用 `:memory:`；符号链接解析后仍须符合要求。日志始终位于持久根目录的 `logs/`。

建议在启动终端和操作 CLI 的终端中使用同一组显式配置：

```bash
export FIELD_RUNTIME_ROOT="$HOME/Library/Application Support/FieldInspect"
export TWIN_DB_PATH="$FIELD_RUNTIME_ROOT/twin.db"
export TWIN_IMPORT_ROOT="$FIELD_RUNTIME_ROOT/imports"
```

已有数据库与归档应直接配置为其原始绝对路径；启动器不搬迁、不覆盖已有数据。换用新的空目录会得到独立的初始演示库，不代表旧数据丢失或真实案例已导入。发现记录缺失时先核对启动日志中的 Database / Imports 路径，不执行重置脚本。

凭据继续使用 `FIELD_AUTH_FILE` 或 `ASTRA_API_TOKEN`，见 [访问身份说明](ACCESS_CONTROL.md)。启动器继承当前环境，不自动读取 shell 配置文件或 API `.env`，不生成凭据，不打印令牌。相对凭据文件路径以启动命令的当前目录解析为绝对路径，配置文件缺失时直接退出；内容错误仍由既有访问层拒绝，不降级为免认证。未配置凭据时保持原本机身份规则。服务只绑定 `127.0.0.1`，API 不信任代理头，网页代理保留原访问保护。启动前须取消 `FIELD_SCHEMA_EXPORT=1` 和非空 `UVICORN_*` 环境变量，避免文档模式、自动重载、外部 socket 或额外环境文件改变固定启动配置。

新建日志及数据目录受当前用户私有权限约束；已有目录权限不被批量重写。凭据和真实运行数据不放入代码或云盘交接目录。

## 启动、停止与日志

```bash
# 从项目根目录启动，保留这个终端
python3 scripts/start-local.py
# 端口确有需要时可显式指定，两端口不能相同
python3 scripts/start-local.py --api-port 8001 --web-port 4174
```

默认网页地址为 `http://127.0.0.1:4173`，API 为 `http://127.0.0.1:8000`。启动器先检查本地依赖文件、构建入口、端口和数据目录锁，再检查 API 依赖可导入；随后启动服务，等待网页、API 健康入口及网页代理健康入口可达，才输出 `Ready`。依赖检查和服务就绪各最多等待 60 秒。该就绪提示仅说明入口可达，不代表业务流程或真实数据验收通过。

停止前在网页暂停批次并等待当前项结束，停止其他 CLI 写入，然后在启动终端按 Ctrl+C；也可向启动器输出的 PID 发送 `kill -TERM <launcher_pid>`。关闭终端时的 SIGHUP 同样触发清理。不使用 `pkill`、按端口杀进程或历史 PID 文件批量停止服务。

启动失败或任一服务退出时，启动器结束本次创建的进程组。停止先发 TERM，最多等待 30 秒；未退出者会被强制结束并记录警告，下一次启动需核对中断处理项。既有批次恢复规则保持不变，未暂停的队列可能在重启后继续处理。数据库、原始归档和日志始终保留。强制杀死启动器（SIGKILL）、系统断电不在其可清理范围内。

每次尝试生成独立 `logs/<时间>-<随机后缀>/`，包括：

- `launcher.log`：本次启动/失败/停止原因及数据路径。
- `dependencies.log`：依赖可导入检查结果，失败时包含具体模块或配置原因。
- `api.log`、`web.log`：服务标准输出与错误。
- `processes.json`：本次启动器/子进程 PID、端口和数据路径，仅作排障记录，不可作为之后杀进程的依据。

缺依赖或构建时按联网准备步骤修复；端口冲突时保留原服务，使用其他空闲端口或由其维护者正常停止。数据目录已被另一启动器使用时先正常停止该启动器，不删除锁文件；锁随进程退出释放。通过其他入口启动的 API 不受此启动器目录锁管理，不得并行写入同一数据库或归档。持久根目录不可写时只能向终端报错，需要先修复该目录权限。

## CLI、更新和恢复

在第二个终端设置与上面一致的环境变量后，复用已有 CLI，例如：

```bash
cd services/api
.venv/bin/python -m app.cli list-rejections
```

场景登记、正式 v2 包导入、备份与验收仍按 [离线导入指南](../OFFLINE_IMPORT.md)。离线时用 `.venv/bin/python` 直接执行，避免 `uv run` 触发同步。不能把指南里的示例相对目录或夹具当作本次真实输入。

代码更新前暂停批次并正常停止服务；停止所有 API/CLI 写入后，独立备份完整数据库及其仍存在的 WAL/SHM 文件、导入根目录和配置，记录摘要。保留旧版本与原数据，更新源码并按准备步骤重建，再使用相同持久路径启动。不支持直接用旧代码打开已升级的数据库来冒充安全回滚；需要回滚时使用匹配的旧代码与更新前完整备份。备份恢复本轮尚未演练，不替代正式包的独立备份核验。
